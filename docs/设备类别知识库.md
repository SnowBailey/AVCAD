# AVCAD 设备类别语义知识库（人可读版）

> 配套机器可读文件：`avcad/data/device_kb.yaml`（14 类语义）；加载器：`avcad/model/category_kb.py`（`get_kb()` / `identify()`）。
> 端口模板（只定义「画哪些口」）在 `avcad/data/device_specs/*.yaml`，与本知识库是两层：本文件管「为什么这么接、怎么用、怎么识别」。

本知识库的目的：**给一个从未见过的新型号，也能立刻判断它属于哪一类、在信号链里干什么、该往上接谁、往下接谁、用什么口、串联/并联/单通道各有什么优劣、和哪些易混类别怎么区分。**

---

## 一、信号链全景（一条典型链路）

```
音源/话筒 ──► 调音台(混音) ──► 处理器(路由/处理) ──► 音箱管理器(分频/限幅) ──► 功放 ──► 音箱(发声)
   │              │                 │                      │                        │
   └ 无线话筒→接收机 ──┘        会议主机(手拉手/同传)       接口箱(I/O边界) ──Dante──► 交换机(星型网络)
                      天线系统(天线/分配器/合路器，空中 RF 链路)
```

- **起点类**：SOURCE（播放源）、WIRELESS_MIC（无线话筒发射端）—— 系统信号从这里产生。
- **核心枢纽**：MIXER（混音）、PROCESSOR（路由/算法）、MIC_HOST（会议）、SWITCH（Dante 网络）。
- **边界/专用**：WIRELESS_RX（接收落地）、SPEAKER_MGR（只服务音箱）、AMP（功率）、IO（远端 I/O）。
- **无线/RF 子系统**：ANTENNA / ANT_DIST / ANT_COMBINE —— 与音频链路并行，靠空中 RF 口连接，不画物理线。
- **终点**：SPEAKER（发声）。

## 二、15 种信号类型速查

| 信号码 | 中文 | 物理形态 | 线型/颜色 | 是否参与自动连线 |
|--------|------|----------|-----------|------------------|
| XLR | 卡侬音频 | XLR/TRS 平衡 | 实线 | 是 |
| AES | 数字音频 | AES3/XLR | 实线 | 是 |
| DANTE | 网络音频 | RJ45/网口 | 实线(蓝) | 是(经交换机) |
| RS232 | 串口控制 | DB9/端子 | 点线 | 否 |
| RF | 射频无线 | BNC/天线 | 空中(air，不画线) | 否(只标口) |
| SPEAKER | 扬声器功率 | Speakon/Phoenix | 实线 | 是 |
| IP | 控制网络 | RJ45/NET | 点线(紫) | 否 |
| GPIO | 通用 IO | 端子 | 点线 | 否 |
| POWER | 电源 | 电源线 | — | 否 |
| OPTICAL | 光纤音频 | 光纤/同轴 | 实线 | 是 |
| TRS | 6.35mm | TRS | 实线 | 是 |
| CONF | 会议总线 | 6芯DIN | 实线 | 是(六芯链) |
| USB | 数字音频 | USB | 实线 | 否 |
| LINK | 级联 | 专用口 | 实线 | 是 |
| WCLK | 字时钟 | BNC | 实线(品红) | 否(数字音频同步基准，点对点接时钟主) |

**关键约定**：`IP`（控制网口）只做中控/监控，**不参与自动音频连线**；真正走网络的是 `DANTE`。处理器/交换机上的「网口」若标 `signal=IP` 是控制口，标 `DANTE` 才是音频口。
**字时钟陷阱 / BNC 接口不是一种信号**：转换器/接口箱/处理器上的 **BNC 同步口**是 `WCLK`（Word Clock，数字音频采样同步基准），**不是** `IP`/`NET` 网络口——曾有人把 YAMAHA RMio64-D 的 WCLK 口误标成 `IP`，已在 AVCAD 中纠正并建模 `WCLK` 信号。
但 **BNC 只是物理接头，不代表固定信号**：同是 BNC，语义取决于设备功能——字时钟=`WCLK`、MADI/AES3 同轴=`AES`、天线射频=`RF`、视频 Genlock / 中控触发=本系统暂不建模。主库 `params.bnc` 只是「带 BNC 口」的标记（共 78 条，含 FURMAN 电源时序器触发口、Modulo Pi 视频 Genlock、IPS 天线 RF 口等），**绝不能整批映射成 WCLK**。见到 BNC 先判它是哪种同步/接口，再定信号。

## 三、14 类设备速查卡片

> 每类：定位 → 上游(信号从哪来) → 下游(到哪去) → 关键接口 → 一句话判别线索。

**1. SOURCE 音源**　起点，只回放不发声。上游：无。下游：调音台/处理器/接口箱/音箱管理器。
关键口：XLR/TRS 线路输出、USB、光纤。判别：清单含「播放/点歌/CD/电脑/DJ/乐器」，只有输出无功率。无冗余。

**2. WIRELESS_MIC 无线话筒(发射端)**　人手里，声电转换+射频发射。上游：无。下游：无线接收机。
关键口：仅 RF 天线口(air，不画线)。判别：手持/领夹/头戴/腰包，只有天线口无音频口。与接收机区别：MIC 是人拿的发射端。

**3. WIRELESS_RX 无线接收机**　机架式，射频→模拟音频落地。上游：无线话筒/天线分配/合路。下游：调音台/处理器/会议主机。
关键口：双 BNC 天线(分集) + XLR 音频输出 + Dante(数字机型)。判别：机架前面板双 BNC + XLR 输出。与天线分配器区别：接收机有音频输出，分配器只有射频口。

**4. ANTENNA 天线**　空中↔线缆射频换能器。上游：接收机/话筒/合路。下游：接收机/分配/合路。
关键口：BNC 射频线 + 空中 RF(air)。判别：只有 RF 口无音频口，外形鞭状/板状/碟形。有源天线需供电。

**5. ANT_DIST 天线分配器**　一入多出，多接收机共享天线。上游：天线/接收机。下游：接收机。
关键口：BNC 输入 + 多路 BNC 输出 + 级联口(cascade)。判别：清单含「分配/分路」，只有射频口。本项目 UM2000ATD 级联口=2，ADS48=0(不级联)。

**6. ANT_COMBINE 天线合路器**　多入一出，多发射机共用天线。上游：接收机/话筒/音源。下游：天线。
关键口：多路 BNC 输入 + 1 路 BNC 输出。判别：清单含「合路/Combiner」多入一出。本项目 UM2000ASD=2入1出。**与分配器正相反：合路多入一出(发射侧)，分配一入多出(接收侧)。**

**7. MIXER 调音台**　多路混音/母线枢纽。上游：音源/接收机/会议主机/接口箱/处理器。下游：处理器/音箱管理器/功放/接口箱。
关键口：多路 XLR 输入(可幻象48V) + 主输出 + Dante + 控制网口。判别：多路输入+主输出，以「人工混音母线」为核心。与处理器区别：调音台是人工混音，处理器是可编程矩阵/算法。

**8. PROCESSOR 音频处理器**　系统大脑：路由/矩阵/均衡/反馈抑制/分频/限幅/延时。上游：调音台/会议主机/音源/接口箱。下游：音箱管理器/功放/接口箱。
关键口：多路 XLR 模拟 + Dante + AES + 控制网口 + GPIO。判别：多路 XLR+Dante+控制网口，做全系统路由/会议处理/房间均衡。**最易与音箱管理器混淆(见第五节)。**

**9. SPEAKER_MGR 音箱管理器**　专管一组音箱：分频+限幅+延时+EQ，输出直接进功放。上游：处理器/调音台。下游：功放。
关键口：全频 XLR 输入 + 分频段 XLR 输出 + 控制网口。判别：输出直接标「进功放」，不接话筒、不做全系统路由。**只服务无源链路；有源箱自带DSP不过管理器(阳哥规则5)。**

**10. MIC_HOST 话筒主机**　手拉手会议核心：主席/代表单元管理、讨论/表决/同传。上游：无线接收机/无线话筒。下游：调音台/处理器/无线接收机。
关键口：6芯DIN CONF 链(CH手拉手/BOC天线盒) + XLR PHX(同传) + XLR MIX(系统音频) + RF(无线单元空中口)。判别：清单含「会议主机/讨论/同传/手拉手/CF63」，多类口。**CF6300.BOX↔CF6300WB.HOST 用六芯；无线单元只认 RF 空中口。**

**11. AMP 功率放大器**　把线路信号放大驱动音箱。上游：音箱管理器/处理器/调音台/接口箱。下游：音箱。
关键口：XLR/Dante 输入 + Speakon/Phoenix 音箱输出。判别：只有小信号输入+功率输出，区别于音箱(终点)。数字功放走交换机(Dante)。功率余量≈2×音箱额定。

**12. SPEAKER 扬声器**　系统终点，电声转换。上游：功放。下游：无。
关键口：无源=Speakon/Phoenix 功率输入；有源=XLR 线路输入 + Dante + 控制网口。判别：只有输入无输出(除返送)。有源箱模拟+Dante 双接入(阳哥规则6)。

**13. IO 音频接口箱**　模拟↔数字/Dante 边界，远端多路汇聚成网。上游：音源/接收机/调音台。下游：交换机/处理器/功放。
关键口：XLR IN(left 舞台侧) + XLR OUT + Dante(right) + AES + 控制网口。判别：左右结构 IN/OUT+Dante，是「远端I/O边界」不做算法。**平级化：DIO/SI/DI Box=SIDE 虚拟 stage，只经 Dante 互通(阳哥规则11)。**

**14. SWITCH 网络交换机**　Dante/网络音频与控制交换中枢，星型联网。上游/下游：所有 Dante 设备。
关键口：RJ45 Dante口(仅标数字) + RJ45 控制口。判别：多 RJ45 无模拟音频口。千兆起步；端口只标数字(阳哥规则7)；冗余双交换机克隆备机(rd_bak)。

## 四、接法通用法则（串联 / 并联 / 单通道）

| 接法 | 含义 | 优点 | 风险/注意 |
|------|------|------|-----------|
| **单通道(点对点)** | 一设备→一设备 | 最清晰、无相位问题、易排查 | 通道占用多 |
| **串联(级联)** | 链式：A→B→C | 扩展带载/通道（手拉手、Dante 网络、分配器级联） | 级联插损累积、故障级联传播、超带载末端失效 |
| **并联** | 一信号分给多路 / 多路汇聚 | 覆盖扩展、分区并行 | 阻抗叠加(音箱并联↓阻抗)、相位/阻抗叠加(音源并接哼声)、须用分配器/调音台汇聚 |

**几条铁律**：
- 多音源**禁止直接并接**同一 XLR（相位抵消+削波）→ 用调音台/分配器汇聚。
- 音箱并联看阻抗：8Ω并→4Ω，再并→2Ω，勿低于功放最低负载。
- 功放桥接两通道→1低音，负载减半，勿低于额定。
- 分配器级联深度≤2级；合路器方向严禁反接(输出当输入烧放大)。
- 无线链路只认 RF 空中口，不画物理线；天线盒与主机用六芯 CONF。

## 五、易混淆类别判别矩阵（最重要）

| 判别对 | 怎么分 | 一句话 |
|--------|--------|--------|
| 处理器 vs 音箱管理器 | 处理器做全系统路由/会议处理/房间均衡；管理器只服务「这一组音箱」，分频+限幅，输出直接进功放，不接话筒 | 接话筒/做路由=处理器；只分频限幅进功放=管理器 |
| 分配器 vs 合路器 | 分配=一入多出(接收侧共享天线)；合路=多入一出(发射侧共用天线) | 多接收机共享天线用分配；多发射机共用天线用合路 |
| 接收机 vs 天线分配器 | 接收机有 XLR 音频输出；分配器只有射频 BNC 口 | 有音频口=接收机；纯射频=分配器 |
| 接收机 vs 天线 | 天线只有 RF 口无音频；接收机有双 BNC+ XLR 输出 | 机架有音频输出=接收机 |
| 功放 vs 音箱 | 功放是功率源、只有小信号输入；音箱是换能终点、只有输入 | 中间放大=功放；最终发声=音箱 |
| 调音台 vs 处理器 | 调音台以人工混音母线为核心；处理器以可编程矩阵/算法为核心 | 人手动混=台；程序路由/处理=器 |
| 接口箱 vs 处理器 | 接口箱是远端 I/O 边界不做算法；处理器做全链路处理 | 只转 I/O 不处理=接口箱 |
| 无线话筒 vs 接收机 | 话筒是人拿的发射端(仅 RF 口)；接收机是机架落地(双 BNC+XLR) | 人手里发射=话筒；机架接收=接收机 |
| 会议主机 vs 接收机 | 主机有 CONF 六芯链+PHX/MIX 音频；接收机只有射频+音频 | 有六芯手拉手链=会议主机 |

## 六、给「新型号」的识别决策流程

拿到一个陌生型号，按三级逻辑判断（对应 `identify()`）：

1. **主库精确命中**：品牌+型号在 `eko_catalog.json` 有记录 → 直接用其 `category`（最权威，confidence=1.0）。
2. **型号片段匹配**：在主库查不到，但型号含已知系列片段（如 `um2000`→无线接收、`rio`→接口箱、`tf`→调音台、`driverack`→音箱管理器、`k2`→音箱、`cdj`→音源）→ 用 `KNOWN_MODELS` 表（confidence=0.8）。
3. **类别词/描述匹配**：以上都不中，用清单描述里的别名词（「调音台」「处理器」「天线」「功放」「会议主机」…）模糊命中（confidence 按命中词数）。
4. **都不中** → 返回 `category=None`，提示人工指定。

**命中率自检**（已验证，见 `category_kb.py __main__`）：UM2000ASD→合路器、ULXD4→接收机、TF5→调音台、DriveRack PA2→管理器、K2→音箱、CDJ-3000→音源、CF6300→会议主机、CF6300WB→天线、UM2000ATD→分配器、RDD12→接口箱、QU16→调音台、RIO3224-D→接口箱 —— 全部正确。

## 七、如何维护（新增型号 / 新类别）

- **新型号已知类别**：直接在主库 `eko_catalog.json`（经 `scripts/build_catalog.py` 的 `MANUAL_CAT`）登记，或写入图例库 → 主库精确命中即生效。
- **型号片段需补**：编辑 `avcad/model/category_kb.py` 的 `KNOWN_MODELS` 表（长串在前，避免被短串抢匹配）。
- **新类别或补充语义**：编辑 `avcad/data/device_kb.yaml`（字段见文件头注释：cn/aliases/role/upstream/downstream/typical_ports/connectivity/matching/identification/typical_models/pitfalls/notes）。
- **端口模板**：端口长什么样在 `avcad/data/device_specs/*.yaml`，与本文件是两层，配套维护。
- 改完跑 `python avcad/model/category_kb.py` 自检识别是否命中；再跑项目验证闭环（pytest + probe_all + validate8）。
