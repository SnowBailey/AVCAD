## 2. 三条链路

### 链路 A：接收机 UM2002 / UM2002L / UM2002H
> 官网：「UM2002 系列**一拖二**无线会议系统采用**真分集双通道**选讯技术，**两只天线接收同一只话筒信号**，大幅度消除接收盲区」
> 官网：「系统音频输出具备**一路 6.35 混合输出及二路 XLR 独立输出**」
> 主库 remark：「套装型号，里面包含 **1 台接收机和 2 台麦克风**；**四天线真分集一拖二，占用天线放大器 4 个通道**」

- **天线需求：4 个 BNC 天线口**
  真分集 = 每通道 2 支天线接收同一只话筒；**双通道 → 2×2 = 4 支天线**
- **音频输出：2×XLR 独立输出（每通道 1 路）+ 1×6.35mm 混合输出**
- **自带简易天线**：出厂配简易天线，可不接外置天线独立工作
- 传输距离 ≥120 m；SC 自动扫频；IR 红外自动对频

### 链路 B：外置天线 UM2000AP / UM2000AT
> 主库 remark（UM2000AP）：「**1 对 = 2 支**，吸顶安装，赠 6m 同轴线*2；用于会议室固定安装 - **360° 全指向**型天线」
> 主库 remark（UM2000AT）：「**1 对 = 2 支**，含安装支架，赠 3m 同轴线*2；用于流动或演讲类会议场景 - 具备 **70° 的信号接收角度**」
> 官网（UM2000AP）：「可有效抵消 **35 米长线缆**传输带来的信号损耗；覆盖 **470~960MHz**」

- **成对出现**：1 对 = 2 支（对应分配器的 2 个输入）
- 接口：**BNC**
- 信号：**RF**
- 线材：**50Ω 同轴线缆**

### 链路 C：天线放大器 UM2000ATD（2 进 / 10 出）
> 官网：「可通过**增强射频信号**来补偿因信号功率分配给多个输出接头时产生的**插入损失**；兼容 **450MHz~970MHz**；具备强大的系统扩展能力，**级联端口能够以链式形式连接多套天线分配系统**」

端口分配规则（阳哥口径）：

```
2 进  ← 一对天线（RF，50Ω 同轴，BNC）
10 出 的分配：
   ├─ 2 出 → 下一台 UM2000ATD 的 2 进   （级联，链式中大型系统）
   └─ 剩余 8 出 → 每 4 口接 1 台 UM2002 接收机 = 2 台
```

- 非末台：`10 − 2(级联) = 8 出 → 2 台接收机`
- **末台**：无需级联，`10 出` 全可用 → `2 台接收机 + 余 2 口备用`
- 单台 UM2000ATD 的接收机容量 = `floor(可用出口数 / 4)`

## 3. 容量测算（供配单/校验用）

| 配置项 | 公式 |
|---|---|
| 单台 ATD 可带接收机 | `(10 − 2×是否需要级联) ÷ 4` 向下取整 |
| N 台 ATD 级联总容量 | `2×N`（末台同样按 2 台计，另余 2 口） |
| 所需 ATD 台数 | `ceil(接收机总数 ÷ 2)` |
| 天线对数 | 每套系统 **1 对**（2 支）接入首台 ATD 的 2 进 |

**本项目（智慧剧场清单）验算**
- 接收机：UM2002 ×4 + UM2002L ×2 + UM2002H ×1 = **7 台**
- 所需 ATD：`ceil(7 ÷ 2) = 4 台` → **清单正好配了 UM2000ATD ×4** ✅
- 天线：**UM2000AP ×1 对** ✅
- 级联链：ATD1 → ATD2 → ATD3 → ATD4(末台)，共 `2×4 = 8` 个接收机位 ≥ 7 ✅

## 4. 程序现状 vs 正确规格 —— 待确认的出入

| 型号 | 程序现状 | 正确规格 | 建议修正 |
|---|---|---|---|
| UM2002 / UM2002L / UM2002H | `params: {channels_hint: 1, bnc: 1}` | **4×BNC 天线输入**、**2×XLR 独立输出** + 1×6.35 混合 | `bnc: 4`、`channels: 2`；输出 2×XLR + 1×6.35 |
| UM2000ATD | `params: {bnc: 3}` | **2 进 / 10 出 = 12 个 BNC** | `bnc_in: 2`、`bnc_out: 10` |
| UM2000AP / UM2000AT | `params: {impedance_ohm: 50, bnc: 1}` | 1 个 BNC 口 / 支，1 对 = 2 支 | 端口正确；**数量需按"对"×2 计** |
| UM2000ATR / UM2000ASD | `category=ANTENNA` | 可选配件（中继 / 分线） | 保持，按需插入链路 |

**注意**：主库 remark 已写明 UM2002 系列「占用天线放大器 4 个通道」，但 `bnc` 参数仍是 1，
两者自相矛盾——这正是需要在图例库/规格里修正的地方。

## 5. 已落盘的实现（2026-08-30）

### 5.1 主库 `eko_catalog.json`

| 型号 | 修正前 | 修正后 |
|---|---|---|
| UM2002 / UM2002L / UM2002H | `category=WIRELESS_MIC`（发射端）<br>`params={channels_hint:1, bnc:1}` | `category=**WIRELESS_RX**`（接收机）<br>`params={channels:2, **antennas:4**}` |
| UM2000ATD | `params={bnc:3}`（→ 默认 2 进 / 4 出） | `params={**inputs:2, outputs:10**}` |

> 关键判断：UM2002 套装含「1 台接收机 + 2 支话筒」，系统图上要画的是**上机架、接天线分配器、输出 XLR** 的接收机，
> 所以分类必须是 `WIRELESS_RX`；若按 `WIRELESS_MIC` 会被排在链路最前端当发射端，导致整条无线链断裂。

### 5.2 规格模板 `device_specs/wireless_rx.yaml`

新增 `antennas` 参数（默认 2），RF 输入口数改为 `count_from: antennas`——
不再写死 2 口，真分集双通道机型（UM2002）取 4 口。

### 5.3 级联连线 `wires/router.py`

新增两个专用函数，替换原来的星型 `_generic_pair`：

- `_antennas_to_first_dist()`：外置天线**只**接首台分配器的进口（第 2 台起由级联供信号）
- `_antenna_distribution()`：
  1. 分配器按 BOM 顺序串成链
  2. 非末台取**末尾 2 个出口**（OUT9/OUT10）级联下一台进口
  3. 剩余可用出口，按**每台接收机的实际天线口数**（UM2002 = 4）依次切分
  4. 末台无需级联，全部出口可用
  5. 出口不足时写 `project.meta["wireless_warnings"]`，不静默漏接

### 5.4 成对展开 `workflow/importers.py`

读取清单「单位」列；单位为 `对 / 副 / pair` 时数量 ×2
（UM2000AP「1 对 = 2 支」，实测清单数量 1 对 → 正确展开为 2 支，分别进首台分配器的 2 个进口）。

### 5.5 回归测试 `tests/test_wireless_cascade.py`（10 条）

覆盖：主库解析、端口展开（4 天线口 / 2×XLR / 2 进 10 出）、级联只从首台发出且用末尾两口、
每 4 口 1 台接收机、天线只进首台、末台用满出口、出口不足告警。

### 5.6 实测（智慧剧场清单）

```
链路: ANTENNA → ANT_DIST → SOURCE(含 7 台 WIRELESS_RX) → PROC_PRE → MIXER → …
UM2000AP ×2  →  ATD#1 (IN1/IN2)
ATD#1 OUT9/OUT10 → ATD#2 IN1/IN2   （级联）
ATD#2 OUT9/OUT10 → ATD#3 IN1/IN2   （级联）
ATD#3 OUT9/OUT10 → ATD#4 IN1/IN2   （级联）
ATD#1 OUT1-4→UM2002#1, OUT5-8→UM2002#2
ATD#2 OUT1-4→UM2002#3, OUT5-8→UM2002#4
ATD#3 OUT1-4→UM2002L#5, OUT5-8→UM2002L#6
ATD#4(末台) OUT1-4→UM2002H#7
校验: 重叠 0 / 斜线 0 / ok=True
```
