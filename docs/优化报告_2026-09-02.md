## 1. 本轮落地项

### 1.1 ★ SPOF 集合判据修复（C1，唯一实证代码缺陷）
- **旧逻辑**（`validate/checks.py`）：`if project.switches and len(project.switches) == 1` —— 只看交换机台数。
  - 漏报「**2 台交换机却把主备都接到同一台**」的情形（主备形同虚设，但 `len==2` 静默通过）。
- **新逻辑**：用语义判据 `S_p ∩ S_b ≠ ∅` —— 主用（非备份）Dante 设备所接交换机集合 与 备用（is_backup）Dante 设备所接交换机集合 有交集即判单点故障。
  - 新增纯函数 `dante_primary_backup_switch_overlap(project)`，从 `Connection`（signal==DANTE）反向推导每台设备所接交换机，集合求交。
  - 拓扑事实：`router._dante_pass` 中 `backup = d.is_backup and sec is not None` → 备机固定走 `sec`、主机走 `prim`，故正常双交换机下两集合无交集，零误报。
- **新错误码**（替代旧 `SPOF`）：
  - `SPOF_NET_SHARED_SWITCH`（ERROR）：主备共用同一台交换机。
  - `SPOF_NET_NO_DUAL_SWITCH`（WARN）：有主备却仅 1 台交换机（克隆/生成未生效的安全网）。
- **`ai/review.py`** 同步：原 `len(proj.switches) == 1` 提示改为复用同一集合判据，避免两层口径不一致。

### 1.2 A 批前置改造（级别嗅探 → 三元组透传）

### 7.1 `SPOF_DSP_SINGLE`（信号链路单点处理器）
- **问题**：原 SPOF 只覆盖「主备共用交换机」的网络层单点。音频链路内部若某台 `PROCESSOR` 处于必经链路上（移除即断链），它本身就是单点故障，此前无任何检查。
- **方案**：纯图论割点判定，复用既有 `Connection` 图，**不引入任何新字段**：
  - 在无向音频信号图上（`XLR/AES/DANTE/TRS/OPTICAL/USB/CONF/LINK/WCLK/SPEAKER`）对每台 `PROCESSOR` 做割点判定；
  - 天然避误报：叶子处理器（度数<2）、星形拓扑（仅接交换机）、已配 `PROCESSOR_BACKUP`/有主备配对的处理器均不报；
  - 级别 `WARN`（设计提示，非硬错误）。
- **新增码**：`SPOF_DSP_SINGLE`（已登记进 `scripts/probe_issue_coverage.py` 的 `VERIFIED_FIRE_OK`）。

### 7.2 术语一致性 linter（规划 §7.2 交付物 34）

### 7.7 落线即挡 第一刀：`DANTE_NO_SWITCH_HOP`（Dante 必须过交换机）
- **动机**：`findings/37` 的 P1/P2「落线即挡」是一整类防御校验。第一刀选风险最低、边界最清的一个——**纯图遍历、零新字段、零误报风险**：AVCAD 拓扑铁律「Dante 一律经交换机」（主备也各自走一台交换机），故两台**非交换机**设备间直接存在 DANTE 连接属可疑拓扑，应人工确认；而正常流程全是 device↔switch，天然不触发。
- **实现**（`avcad/validate/checks.py`）：
  - 新增 `dante_device_to_device_links(project)`：遍历 `project.connections`，筛出 `signal==DANTE` 且**两端 `category` 都不是 `SWITCH`** 的连接。
  - `validate()` 中对每个命中发 `Issue("WARN", "DANTE_NO_SWITCH_HOP", ...)`。级别 **WARN**（设计提示，非硬错误）。
- **零误报论证**：判定只用 `category=="SWITCH"` 与 `signal==DANTE`，不引入任何新字段；XLR/AES 等非 DANTE 信号、device↔switch 的 DANTE 连接均不触发。
- **回归**（`avcad/tests/test_redundancy_failover.py`）：新增 3 条 `DANTE_NO_SWITCH_HOP` 用例——①设备↔设备 DANTE 直连**必须报**；②device↔switch DANTE 连接**不误报**；③非 DANTE 信号直连**不误报**。
- **覆盖率**：`scripts/probe_issue_coverage.py` 的 `VERIFIED_FIRE_OK` 新增 `DANTE_NO_SWITCH_HOP`，实跑确认已识别、无「未验证且从不触发」的校验码。
- **测试**：`pytest avcad/tests -q` → **302 passed**（299 + 3 新增）。

### 7.8 落线即挡 第二刀：`DANTE_NO_NETWORK`（Dante 子图必须含交换机）
- **动机**：第一刀 `DANTE_NO_SWITCH_HOP` 是「逐条连接」视角。仍有漏网形态——多台 Dante 设备互相 device↔device 直连、整张 Dante 子图**一台交换机都没有**（网络根本没搭起来）。本刀补「连通分量」视角，与一刀合起来彻底堵死「Dante 不经交换机」。
- **实现**（`avcad/validate/checks.py`）：
  - 新增 `dante_components_without_switch(project)`：在 DANTE 边构成的**无向图**上做连通分量遍历；仅把「确有 DANTE 边」的设备纳入（Dante 端口留空未用的不算），若某分量不含任何 `SWITCH` 节点则该分量内全部设备命中。
  - `validate()` 中对每个命中发 `Issue("WARN", "DANTE_NO_NETWORK", ...)`。级别 **WARN**。
- **零误报论证**：完备 Dante 部署里每台设备所在分量必含交换机；只统计确有 DANTE 边的设备，故正常 device↔switch 拓扑与「端口可选未用」均不触发。
- **回归**（`avcad/tests/test_redundancy_failover.py`）：新增 3 条 `DANTE_NO_NETWORK` 用例——①无交换机 Dante 簇（D1—D2）**两台都报**；②含交换机的分量**不误报**；③设备经 peer 中转最终连到交换机（连通分量含交换机）**不误报**。
- **覆盖率**：`scripts/probe_issue_coverage.py` 的 `VERIFIED_FIRE_OK` 登记 `DANTE_NO_NETWORK`，实跑确认已识别、无「未验证且从不触发」的校验码。
- **测试**：`pytest avcad/tests -q` → **305 passed**（302 + 3 新增）。
- **落线即挡家族现状**：`DANTE_NO_SWITCH_HOP`（逐条连接）+ `DANTE_NO_NETWORK`（连通分量）两刀合围。后续可做的第三刀（拓扑环/跨域直连）需结合「数据先于规则」评估，避免误报，暂不擅自扩。

  - **症状**：循环里 `pending.pop(0)` 写在容量校验 `if i + need > len(usable): break` **之前**。一旦某台接收机所需天线口超过本台分配器剩余出口，它已被 pop 出 `pending` 又被 `break` 丢弃——**既不连线、也不进末尾 `if pending:` 的「出口不足」告警**，从图上活生生消失，零报错。
  - **修复**：把 `pending.pop(0)` 挪到容量校验**通过之后**（无 RF 口的接收机仍先 pop 再 `continue`，否则会卡死在 while）。容量不够时保留在 `pending`，交给下一台分配器；确实接不到的，末尾告警一个不漏。零新字段。

- **S2 双源注入同一输入口**（`wires/router.py` 三个配对助手）：
  - **症状**：`_generic_pair` / `_connect_mic_host` / `_failover` 向目标输入口 `project.connections.append`，**不检查该口是否已被占用**。两个不同信号源接入同一 `(to_uid, to_port)` 物理上不可行，且 `_dedup` 只按完整 `from/to` 元组去重，抓不到「不同源 → 同一输入口」。典型触发：步骤 1 通用配对与步骤 2 `_connect_sources_to_core` 都把音源喂给同一台核心级，索引对齐即双源。
  - **修复**（根因拦截，三处共用）：`connect()` 入口建 `project._used_in = {}` 占用表；新增 `_claim_input(project, conn)`——`(to_uid, to_port)` 已被占用则跳过 append 并写 `meta["double_source_warnings"]`，否则登记并 append。三处 `append(Connection(...))` 统一改为 `_claim_input(project, Connection(...))`。
