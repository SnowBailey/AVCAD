## 2. 三条链路（官方原文支撑）

### 链路 A：主机 ↔ 有线会议单元（手拉手串行）
> 原文：「会议主机与有线会议单元、天线盒均采用**专用六芯主缆**连接，传输距离达 100 米。」
> 原文：「有线系统**单元间采用 T 型线连接**，便于扩展和移动。」
> 原文（CF6321 / CF6312 页）：「与单元、主机均通过**六芯专用 T 型线**连接。」

- 拓扑：**总线式串联（手拉手 / daisy chain）**，不是星型
  `CF6300 → 单元1 → 单元2 → 单元3 → 单元4 → 单元5`
- 线缆：六芯专用 T 型线（每台单元两端各一个 T 型接口，一进一出）
- 距离：主机到最远单元 ≤ 100 m（含单元间串联累计）
- **环形备份**：
  > 原文：「支持有线单元**环形手拉手连接，某台单元故障不影响整套系统工作**。」
  即末端单元可再回一根线到主机形成环网，单点故障自动绕行。

### 链路 B：主机 ↔ 天线盒 ↔ 无线会议单元
> 原文（CF6300WB 页）：「采用无线数字 **U 段**技术实现声音信号传输……通过 **6 芯专用线缆**连接无线会议主机**信号传输及供电**，与主机之间最远距离可达 **100 米**，具备**半径 80 米**的超远信号接收范围。」
> 原文（CF6360 页）：「以无线数字 **U 段**技术实现与**天线盒**声音信号之间的传输。」

- 两段：
  1. `CF6300WB ──6芯专用主缆── CF6300`（**信号 + 供电**都由主机给，天线盒无需独立电源）≤ 100 m
  2. `无线单元 ⇢UHF 无线⇢ CF6300WB`（数字跳频，半径 80 m 内可自由移动）
- 无线单元**没有任何物理端口**（阳哥确认），图上不画接口，只画无线链路
- 单台天线盒可覆盖半径 80 m；超大/异形会场可加 CF6300RP 中继器

### 链路 C：主机 → 调音台 / 音频处理器
- `CF6300 ──XLR MIX 输出── 调音台`
- 现状程序建模：右侧 **4×PHX（凤凰端子分区输出）+ 1×XLR MIX 输出**
  （对应官方「内置 DSP 模块……支持音频**四分区**输入/输出」）
- 所有有线 + 无线单元的音频**只在主机汇合后统一输出**，不会每台单元单独拉线到调音台

## 3. 关键结论（写程序时要遵守）

1. **有线单元不是无线设备**。官方明确是六芯 T 型线手拉手，程序里不应给它们打 `wireless` 特性。
   只有 **CF6360 / CF6350** 是真正的无线单元。
2. **整条会讨链在系统图上只对外呈现一个音频出口**：CF6300 的 XLR MIX（+ 可选分区 PHX）。
   不应出现「每台话筒 → 调音台」的星型连线。
3. **无线单元无端口**：CF6350 / CF6360 在图例里端口数为 0，靠 UHF 链路连到 CF6300WB。
4. **CF6300WB 的 6 芯口是「输入」方向**（接收无线信号回传主机）+ 由主机供电。
5. **充电箱 CF6300WCB / 中继器 CF6300RP 不出系统图**（配件，不传音频）。

## 4. 已落盘的修正（2026-08-30）

| 型号 | 修正前 | 修正后 | 依据 |
|---|---|---|---|
| CF6321 / CF6320 / CF6319L / CF6319S / CF6311 / CF6310 | `features` 含 **`wireless`** | 去掉 `wireless` | 官方：六芯专用 T 型线**有线**手拉手 |
| CF6312 | `[analog, control, phantom, wireless]` | `[analog, control, phantom]` | 数模双备份保留 `analog`/`phantom`；但也是有线单元 |
| CF6300WCB 充电箱 | `category=SOURCE`（会出图） | `category=None` → 排除出图 | 只充电，不传音频 |

### 附带修复的既有 bug：`category=None` 的「不出图」约定形同虚设

`product_resolver.resolve()` 对主库后置条目会打 `_resolved="eko-deferred:…"` 并**故意不设 category**，
但 `importers.build_entries()` 随后无条件兜底 `classify_category(name) or "IO"`，把后置设备又变成 IO 箱子；
而 `_drawable` 标记**全项目从未被消费**。

修正后的规则（`build_entries`）：
1. 主库给了类别 → 直接用；
2. 主库未给类别 → 先试名称关键词兜底（**QU-16 →「数字调音台」→ MIXER 必须保留**）；
3. 名称也命中不到、且主库明确后置（`eko-deferred`）→ **排除出图**，计入 dropped 提示；
4. 名称命中不到、但主库也没匹配到 → 保留 `IO` 兜底（避免未收录设备被静默丢弃）。

回归测试：`test_deferred_keeps_name_fallback_but_drops_accessories`。

**已知待办**：有线单元的「星型连线 → 手拉手串联」渲染尚未实现，需改 `core/build.py` 的连线生成。

| 型号 | 现状 | 待办 |
|---|---|---|
| CF6300 | `category=IO`，4×PHX out + 1×XLR MIX out | 与官方四分区 + MIX 一致，保留 |
| CF6300WB | `category=IO`，4×6P_DIN in + 1×XLR in + 顶部 RJ45/UPDATE/RS485/RS232 | 阳哥此前已确认，保留 |
| CF6300RP 中继器 | `category=None`，不出图 | 一致 |
