# 品牌主库（eko_catalog.json）矫正记录

> 背景：系统图只能由「真实参与音频信号链路的设备」构成。主库里混入的
> 线缆、安装架、控制面板、视频设备、服务器、软件等，一旦出现在清单里
> 就会被当成设备画进图，产生孤立节点与错误连线。
>
> 目标：让 **`no_draw`（不出图）** 成为可靠、可审计的显式标记，
> 压过「按名称关键词兜底分类」这条不可靠路径。

---

## 1. 核心机制

### 1.1 为什么不能复用 `drawable`

`catalog_resolver.resolve()` 返回的 `drawable` 是**推导值**
（`bool(spec) and 品牌未排除`），绝大多数条目都是 `False`。

拿它当「不出图」标记会误杀 **QU-16** 这类**必须靠名称兜底成 MIXER**
的型号（「数字调音台」→ MIXER）。这是设计意图，不是 bug。

→ 必须用**专用字段** `no_draw`，链路：

```
eko_catalog.json  { no_draw: true }
   ↓ catalog_resolver.Catalog.resolve()  透传
product_resolver  打 entry["_no_draw"]
   ↓ importers.build_entries()  直接排除，不走 classify_category
```

典型受益场景：「天线延长线两端BNC公头/10米」——名称含「天线」，
会被 `CATEGORY_KW` 兜底成 ANTENNA，只有 `no_draw` 能压住。

### 1.2 分类判定优先级

```
1. 主库显式 no_draw          → 排除（最高优先级）
2. 主库给了 category          → 直接用
3. 主库没给 → 名称关键词兜底   → QU-16 → MIXER 走这条路
4. 名称也命中不到 + 主库后置   → 排除，计入「已排除非信号设备」
```

### 1.3 占位项排除（importers）

造价清单里的「按需保留 / 自配 / 甲供 / 待定 / 暂定 / 按实结算 / 另计 / 不含」
这类占位行，无品牌无型号，无法建模。

`is_placeholder()` **仅在 brand 与 model 同时为空时**才排除——
否则「自配机柜」这类带型号的真实设备会被误杀。

好处：用户不必每次在第②步手动点「不需要」。

## 2. 矫正方法论（可复用于其他品牌）

1. **按 category 分组扫**，重点看两类：
   - `None` 类（可能漏掉该出图的设备）
   - 设备类里的**配件混入**

2. **配件词表扫描**：28 个词
   （架/罩/车/箱/线缆/线/配件/适配器/话筒夹/防风罩/机柜/电源分配…）
   + 条件「category 属设备类」→ 批量 `no_draw`

3. **⚠️ 必须留误报豁免**——纯关键词会误杀真实设备。实测 6 条：

   | 型号 | 名称 | 为什么不能排除 |
   |---|---|---|
   | AUDIX M55W / M55WHC / M55WS / M55WD | 悬吊话筒（**线缆吊挂**） | 「线缆吊挂」是安装方式描述，不是线缆配件 |
   | Apart SPH16 / SPH20 | 5"/8" 两分频垂饰球**吊挂**扬声器 | 「吊挂」是音箱形态，不是吊挂件 |

   → **批量前务必逐条看名称**，不要只看关键词命中。

4. **名称含「扬声器/音箱」的配件**（「监听扬声器配件」「音箱支架适配件」）
   会被 `CATEGORY_KW` 兜底成 SPEAKER，**只能靠主库 `no_draw` 压住**，
   `RIGGING` 关键词管不了。

5. **改前备份到 `/tmp`**，不要放仓库目录（`git add -A` 会误提交 1MB 备份；
   虽然 `.gitignore` 已含 `.bak.*`，仍优先用 `/tmp`）。

6. **改完双验证**：全量测试 + 真实清单导入/出图。

## 6. 待办：连线逻辑缺口（数据阶段已就位，等生成逻辑补齐）

`CF6300WB` 归 `ANTENNA` 后，实测暴露两个**连线/建模**缺口（不影响数据正确性）：

| # | 现象 | 正确链路应该是 |
|---|---|---|
| 1 | CF6300WB 成孤立节点（0 连线）。它所有端口都是 `role=in`（4×DIN + XLR + RJ45/UPDATE/RS485/RS232），没有出口 | `CF6350 无线会议单元 ⇢RF⇢ CF6300WB ──6芯主缆──▶ CF6300(MIC_HOST)` |
| 2 | CF6350 被套用 `source` 默认模板，生成了 1×XLR OUT | 无线会议单元**无物理端口**，应 `ports_override=[]` |

> 说明：改动**前** CF6300WB 是 `IO`，被连成
> `QU-16 调音台 OUT → CF6300WB DIN` 共 5 条——**方向完全反了**。
> 改归 `ANTENNA` 后这 5 条错误连线消失，孤立是"不再画错"的代价，
> 待连线逻辑补上正确链路即可。
