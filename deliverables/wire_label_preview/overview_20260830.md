## 二、补齐 CAD 导出入口

### 新增按钮

第 5 步生成后，出现醒目的主按钮 **「⤓ 导出 CAD」**；原「导出 DXF」保留为「快速下载 DXF」（下载到浏览器默认目录）。

### 导出流程

1. 点「导出 CAD」 → 弹出模态框。
2. 默认文件名：`工程名_YYYYMMDD-HHmm.dxf`。
3. 点「选择文件夹…」 → **弹出系统原生文件夹选择窗口**：
   - macOS：`osascript choose folder`
   - Windows：PowerShell `FolderBrowserDialog`
   - Linux：`zenity` 或 `tkinter`
4. 点「开始导出」 → 进度条分三段：
   - 12%：正在生成图纸（模块 / 连线 / 线标 / 端口）
   - 45%：正在写出 DXF（R2010）
   - 100%：导出完成
5. 完成后显示：**文件大小、绝对保存路径**，并提供 **「打开所在文件夹」** 入口。

### 错误提示

- 未选目录 / 目录不存在 / 不是文件夹
- **目录无写入权限**：明确提示「没有写入权限：xxx（请换一个目录，或在系统中授予该目录的写权限）」
- 写入失败 / 图纸生成失败：前端弹窗结果区红字展示具体原因

### 技术要点

- 后端新增三个端点：
  - `POST /api/pick-folder`：弹出系统文件夹对话框，返回路径。
  - `POST /api/export-save`：复用现有 `/api/export` 的 DXF 构建逻辑，按指定目录和文件名落盘。
  - `POST /api/open-folder`：macOS `open`、Windows `explorer`、Linux `xdg-open`。
- 原生弹窗不可用时自动退回浏览器的 `showDirectoryPicker()`（File System Access API），但会提示该方式无法「打开所在文件夹」。
- 文件名自动清理非法字符 `<>:"/\\|?*`，并强制以 `.dxf` 结尾。

### 2. 第 3 步图例回填的 bug（已修）

**现象**：你把某个图例改成 `IN × 12` 并保存，重新导入清单后第 3 步却显示成 `IN × 1`。

**根因**：第 3 步有两条数据来源，格式不同：

| 来源 | 格式 | 示例 |
|---|---|---|
| `/api/run`（引擎推断） | **展开后的实例**，没有 count | `IN1 … IN12` |
| `/api/legend` 缓存（你保存的） | **类 + 数量** | `{label:"IN", count:12}` |

而 `aggregatePorts()` 对每条一律 `count++`，**完全忽略了「类」条目自带的 `count`**。于是你保存的 `IN×12` 被当成 1 条，显示成 `IN×1`。

**修复**：
```js
const c = parseInt(p.count, 10);
m[key].count += (isFinite(c) && c > 0) ? c : 1;
```

**回归脚本**：`scripts/e2e_legend_roundtrip.js`
- 会话①：把 TF5 的 IN 改成 7 → 保存 → 校验服务端记录 `IN.count === 7`
- 会话②：全新页面 → 重新导入同一份清单 → 断言第 3 步显示 `IN×7`（端口总数 11）
